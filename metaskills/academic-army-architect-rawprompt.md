# 纯手打的prompts

这个skill已经完成，我很满意，接下来我想记录一下这个skill的写作经验，我放上了之前对话中的所有user prompt，请帮我总结一下，明确我需要一个什么样的skill，这个skill设计时需要注意哪些要点，总结一下这个skill背后的逻辑，可以作为prompt拿去给写skill的agent编写这个skill： 

1. 我和一个编写skill的agent进行了多轮交互编写skill，以下是我这边每次提出的问题，请帮我明确需求，具体说明我想要的一个优秀的skill是什么样的？并给出一份prompt，我去交给编写skill的agent完善skill 

2. 我正在编写一套基于codex的autoresearch工具，目前正在编写一个为论文制定论文蓝图的skill。请看一下SIGGRAPH/CVPR/SIGCOMM/NSDI等顶级会议上的高引论文，分析一下这些高引论文为何优秀，分析一个优秀的论文蓝图应该重点明确哪些方面的内容，并在网上找找相关的autoresearch工具，分析他们是怎么写的，分析一个优秀的论文蓝图skill应该怎么写最好。 

3. 我已经有了一个deepresearch的mcp工具（其实就是输入prompt通过openai API转发给gpt-5.5+web search的API）所以有些可以现场搜索得到的信息不需要保存在skill里。看看这样怎么设计一下更简洁？

4. 我还想进一步让skill用用户对话的语言输出对论文蓝图的解释和思考流程

5. 我想让skill输出的解释中分析一下目标venue和相关领域的高引论文的优点，提炼其优秀模式，并用于解释当前蓝图取舍，怎么写

6. 现在的输出格式还不太一致，我想输出一个英文的论文蓝图markdown文件和一个用用户语言的论文蓝图解释markdown，论文蓝图里就只放论文蓝图，论文蓝图解释里就只放论文蓝图解释，要在skill里明确。另外在分析写作手法的时候用到的论文必须得新，代表了现在审稿人喜欢的story telling和写作风格，分析methods 数据集等方面的论文就可以稍微老一点没关系。看看怎么修改一下这个skill

7. 现在的论文蓝图解释里好像只包含了核心重点内容，很不错，但是我还想再加上一些对论文蓝图内容的详细解释，对论文蓝图的内容逐个解释他们对应哪个核心重点内容和关联，怎么修改一下

8. 感觉生成的skill里有些和论文本身无关的东西，比如Reproducibility and Artifact Plan里出现了一个Artifact cautions告诉用户Do not assume reviewers will run code？感觉这个和论文关系不大。看看skill里还有没有输出类似东西的地方，改一下。另外，我深入想了一下，感觉还需要进一步明确：这个论文蓝图主要是给AI看的不是给人看的，只需要客观描述方案即可，不应该有比如Assumptions to validate或者Artifact cautions告诉用户Do not assume reviewers will run code这种面向用户的部分，看看怎么改一下这个skill使其输出的论文蓝图更接近一种可实施的“方案”，论文蓝图解释里给用户解释这个“方案”设计成这样的原因。

9. 现在这种用编号解释蓝图的方法给人看太不友好了，到处引用来引用去的没法看，怎么改一下写作方式能让蓝图解释更易读

10. 还是感觉不够自然，感觉论文蓝图不是必须要用编号，每个部分有自己的1.2.3就行了，论文蓝图解释里可以把论文蓝图中的每一条都拿出来解释一下，解释其和核心思想或其他部分的关联，这样就不需要c1c2c3b1b2b3这样的编号了

11. 看一下这个输出的论文蓝图解释，感觉输出了很多skill里的东西，，比如“为什么正式蓝图采用实施计划格式”这个是skill确定好的流程不需要输出。分析一下为什么会输出这样的内容，应该让编写skill的agent如何修改

12. 上网搜索一下AI生成文本中的defensive现象，在编写这个skill的时候不要过度defensive，要通过正向语言严格限制skill只能做什么，而不是加反向的限制条件限制skill不能做什么，看看如何修改这个skill

13. 突然想明白了，论文蓝图解释文件的功能应该是让用户确认蓝图文件中的项目是否合理，所以才需要展示蓝图中的每一条内容和其他内容的关系，skill里现在确实写了一些规则，但是没有强调“用户确认蓝图文件中的项目是否合理”的主要功能。蓝图解释文件应该要能让用户理解整个论文的核心出发点（也就是“为什么要这么写”）并告诉用户蓝图文件中的每个细节都是如何从这些核心出发点推导出来的，这样用户发现了不合理的地方可以知道这个不合理的地方是哪个出发点想错了或者从出发点到这个不合理的地方的中间有哪里想错了，而不是要靠自己猜这里是怎么想出来的。看看这个skill该怎么改一下更好

14. 现在的论文蓝图解释中对section的引用还是用编号指代的，不方便理解，现在section都有自己的标题了，其实可以用标题或近义词指代，更方便阅读，看看怎么改一下skill

15. 论文蓝图解释目前只有解释，没有对论文蓝图中重点内容的概括，需要和论文蓝图对照着看，不太方便，论文蓝图解释中在每个解释前还是需要复述一下论文蓝图里的正文内容，更方便看。看看怎么改一下skill。

16. 我之后还会在论文蓝图的基础上进一步运行具体论文内容编排规划、实验规划、绘图规划等更多具体的规划skill，他们会包含不同的专业能力有倾向性地重点规划论文的不同部分，所以论文蓝图中不需要对论文内容、实验、绘图做出具体安排，而是需要明确论文的核心信息以供后续skill具体规划。帮我想想这种情况下论文蓝图应该明确哪些核心信息能让后续步骤高效规划？

17. 输出的内容还是有些太细节了，有很多地方在反问用户在几个精确的方向上做选择，看看怎么改一下让这个skill更偏向战略规划，输出战略层面能确定的内容，减少对战术层面的关注

18. 感觉要让skill偏向战略规划可以将其做成“目标导向”的，明确idea后将这个idea分解成各种目标，以目标为导向组织论文蓝图，在论文蓝图解释中就解释每个目标背后的思想和联系，以及论文蓝图中的各种安排都如何帮助论文达成目标。怎么改一下skill

19. 在论文蓝图解释的开头记录一下用户已经明确了哪些东西。看看怎么改一下
